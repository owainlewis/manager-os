# Find the bottleneck

## When to use
Once a month, or before changing how the team works.

## Reads
- Linear issue history for the last month

## Steps
1. For each status, work out the average and longest time issues sat there.
2. Name the status where work waits longest.
3. Give three example issues that waited there, with links and wait times.
4. Compare with last month's result, if there is one.

## Output
A comment with a table of statuses and waits, the bottleneck, the examples and how each number was calculated.

## Rules
- Name steps, not people.
- If the data has gaps, say where.
